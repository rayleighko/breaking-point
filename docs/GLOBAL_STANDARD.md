# 글로벌 기준과 한국어 설명 원칙

Breaking Point의 목표는 외국 사례를 그대로 수입하는 것이 아닙니다. 대한민국의 software engineer가 지역과 회사가 달라져도 같은 근거로 토론하고, 자신의 환경에 맞게 판단할 수 있는 공통 언어를 만드는 것입니다.

## 무엇을 글로벌 기준이라고 부르는가

자료의 성격을 다음과 같이 구분합니다.

| 구분                     | 의미                                                                 | 표현 방식                                           |
| ------------------------ | -------------------------------------------------------------------- | --------------------------------------------------- |
| International standard   | ISO, IEC, W3C, IETF RFC처럼 공개 절차로 합의된 specification         | 표준 번호, version과 normative source를 표시합니다. |
| De facto standard        | 공식 표준은 아니지만 여러 생태계에서 상호운용의 기준이 된 기술       | 채택 범위와 예외를 함께 설명합니다.                 |
| Vendor behavior          | AWS, Kubernetes, PostgreSQL 같은 제품의 현재 동작과 제약             | 공식 문서, version과 확인 날짜를 표시합니다.        |
| Industry practice        | 여러 production 조직에서 반복해서 쓰이지만 상황에 따라 달라지는 접근 | 전제, trade-off와 반례를 포함합니다.                |
| Company case             | 한 회사가 특정 규모와 조직에서 선택한 구현                           | 보편적 정답이 아닌 사례로 표시합니다.               |
| Practitioner perspective | 저자, 발표자와 community의 해석 또는 전망                            | 사실과 분리해 관점으로 표시합니다.                  |

유명한 회사가 사용한다는 사실만으로 global standard라고 부르지 않습니다. 반대로 국내 사례라는 이유로 배제하지도 않습니다. 재현 가능한 evidence와 다른 환경으로 옮길 수 있는 pattern이 있는지를 봅니다.

## 한국어로 전달하는 방식

- 사용자에게 보이는 문장은 존칭을 사용한 자연스러운 한국어로 작성합니다.
- 기술 고유명사, API, metric과 pattern은 공식 원어 표기를 유지합니다.
- 번역어만으로 검색이 어려운 경우 첫 등장에 `한국어 설명(English term)`을 함께 씁니다.
- 불필요하게 모든 명사를 영어로 바꾸지 않습니다. 영어는 정확한 검색과 협업에 도움이 될 때 사용합니다.
- 학술적으로 존재하는 한국어 번역이라도 실제 개발 현장에서 거의 쓰지 않으면 대표 용어로 삼지 않습니다.
- 용어의 정확성은 번역 가능성뿐 아니라 실제 community의 사용 빈도와 검색 가능성으로 검수합니다.
- 예시는 한국 사용자에게 이해되는 맥락을 사용할 수 있지만 특정 국내 기업의 내부 구조를 추측하지 않습니다.

## 랩에서 비교할 것

1. vendor와 무관한 generic pattern을 먼저 시뮬레이션합니다.
2. 표준 또는 원전에서 정의한 용어를 연결합니다.
3. AWS, Kubernetes, PostgreSQL 등의 concrete implementation을 비교합니다.
4. 지역별 법률, latency, 비용과 운영 인력처럼 달라질 수 있는 constraint를 표시합니다.
5. 사용자가 자신의 환경에서 검증할 metric과 experiment를 제공합니다.

## 피해야 할 표현

- “해외에서는 모두 이렇게 합니다.”
- “Big Tech가 사용하므로 정답입니다.”
- version과 출처가 없는 기본값 또는 quota
- 회사 사례를 표준이나 인과관계의 증거처럼 사용하는 문장
- 번역 과정에서 원래 용어의 적용 범위를 넓히거나 줄이는 설명
