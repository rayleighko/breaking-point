# 지식과 출처 관리 원칙

이 문서는 랩, 주제 위키와 AI 코치가 사실을 고르는 기준입니다.

## 출처의 우선순위

1. 국제 표준 기구의 specification, RFC와 개념을 처음 제안하거나 정리한 원전·논문
2. 제품과 기술의 공식 문서
3. 대학의 공개 강의와 교재
4. 검증 가능한 실무 참고 자료

4번 자료는 학습 범위, 사례와 관점을 탐색하는 데 사용합니다. 사실을 단정할 때는 가능하면 1~3번 출처로 다시 확인합니다. 개인의 미래 전망과 의견은 사실이 아니라 관점으로 표시합니다.

## 저작권과 독창성

- 외부 서비스의 문제 문장, test case, 해설, 도표와 분류 순서를 복제하거나 번역하지 않습니다.
- 공개된 idea와 사실을 참고하되 scenario, 제약, 수치, UI, 설명과 검증 코드는 직접 만듭니다.
- 인용이 필요한 경우 짧게 인용하고 저자와 원문 link를 가까이에 표시합니다.
- 유료 자료를 요약해 원문을 대체하지 않습니다. 무엇을 학습할 수 있는지만 설명하고 원문으로 안내합니다.
- 외부 회사명을 권위의 근거로 사용하지 않습니다. 재현 가능한 현상과 evidence로 설명합니다.

## 주제별 검수

- 이름이 있는 방법론은 최초 저자 또는 대표 원전을 확인합니다.
- vendor 설정값과 quota는 발행 시점의 공식 문서를 확인합니다.
- 빠르게 변하는 AI 도구와 model 정보에는 확인 날짜를 남깁니다.
- 생태학의 `carrying capacity`처럼 다른 분야에서 가져온 은유는 업계의 실제 표준 용어와 구분합니다.
- 출처끼리 해석이 다르면 하나를 정답으로 숨기지 않고 적용 범위와 차이를 설명합니다.
- `global standard`, `industry practice`, `vendor behavior`, `company case`를 같은 권위로 섞지 않습니다.
- 특정 국가나 기업의 사례는 보편적인 정답이 아니라 constraint가 있는 적용 사례로 표시합니다.
