# Learning UX checklist

## Before interaction

- The page states the question before terminology.
- One primary action is visually and semantically clear.
- Default values demonstrate a meaningful, safe scenario.
- Model limitations are visible near the result, not hidden in documentation.

## During interaction

- Controls update the visualization without surprising resets.
- Running, paused, disabled and selected states are distinguishable without color alone.
- Values include units and explain their consequence.
- Animation conveys state rather than decoration and respects reduced motion.

## Result and recovery

- The result connects observation, arithmetic and concept name.
- Errors say what is wrong and how to recover without deleting valid input.
- The learner can reset, compare, share or report a reproducible Scenario.
- A challenge explains constraints and cannot pass by blindly adding resources.

## Browser evidence

- Complete the primary task once.
- Trigger one invalid-input path.
- Check 375px width for document-level horizontal overflow.
- Confirm keyboard-accessible names for interactive controls.
- Check browser console errors after hydration and interaction.
- Note Canvas frame cost or object bound for high-volume simulation changes.
